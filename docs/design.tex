\section{Overview}
The \code{funsearch} Gas City pack orchestrates evolutionary program search in the
FunSearch / AlphaEvolve lineage \cite{funsearch,alphaevolve,ellenberg,kitft}.
A user supplies a problem directory and an evaluator with a C interface.
The pack supplies the engine, worker, and mutator agent role. All problem
knowledge belongs to the evaluator; the pack works in any rig.

New candidate programs are whole source files written by a small coding agent,
rather than a single model completion. This is the agentic variation operator
pattern \cite{avo}: a mutator reads parents and feedback, writes a child,
and can compile and test it before submitting. Authoritative scoring still
belongs to the engine and evaluator.

The design trades sample volume for effort per child. The intended comparison
is FunSearch at roughly millions of samples, AlphaEvolve at thousands, and this
pack at hundreds. These are order-of-magnitude planning estimates, not comparable
benchmark measurements or results of our acceptance run. The epic expects about
50--100 times fewer samples than FunSearch, with better prepared candidates.
The acceptance run measures throughput and validity to test that expectation.
Related work includes sample-efficient evolution \cite{shinka} and analysis of
what evolutionary coding agents evolve \cite{agents-evolve}.

\section{Run life cycle}
\begin{enumerate}
\item An experimenter prepares a problem and uses \code{check} for pre-flight.
The one-step v2 run formula starts a run with its instance, optional overrides
and required notification recipient. The engine validates the problem, builds
the evaluator, and requires the compiled seed to score \code{FS\_OK}.
\item The engine saves the problem inputs, configuration and the copy of the
evaluator library's directory that scored the seed, and starts its detached observer and daemon. The
daemon starts its worker pools and then runs the start hook itself, before
dispatching any evaluation; the launcher waits for that readiness.
The hook creates a run bead and K raw-routed slot beads and registers the engine
PID. The launcher prints the run ID and path and returns without waiting for search.
\item Each fresh mutator session claims a slot and performs N tasks:
\code{next-task} $\to$ read \code{TASK.md} $\to$ write \code{child.c} $\to$
bounded \code{try} $\to$ \code{submit}. After N accepted submissions it releases
the still-routed, unassigned, open slot, writes a retirement receipt, and calls
\code{gc runtime drain-ack}. Another fresh session takes the seat. Rejection
does not consume the task; a fresh session can also resume an unfinished task.
\item Duration, maximum submitted evaluations, plateau, or explicit \code{stop}
ends the run. Task commands then report \code{RUN\_OVER}, exiting 3.
Mutators close their slots and drain. Queued requests are rejected; in-flight
scoring may finish for at most 120 seconds.
\item The engine writes \code{summary.json}, exports \code{best.c} and
\code{top/<rank>-<score>.c}, backs up SQLite, and stops workers. It invokes the
finish hook with the run directory and \code{FS\_RUN\_DIR} set, then exits.
\item The finish hook updates the run summary, force-closes remaining slot
beads before closing their parent run bead, mails \code{notify}, then deletes
the active registry entry. No result or source is automatically committed.
\item If the engine dies before clean finish, the condition-triggered sweep runs
with active entries and a last-sweep age greater than 30 minutes. A dead PID
without a terminal summary is marked failed with reason ``engine died'':
\code{funsearch run recover} rewrites outputs from the live database or the newest
readable snapshot. A terminal summary is preserved and its finish
hook retried. Failed deliveries retain the entry; the sweep always updates its
timestamp under a city-wide lock.
\end{enumerate}
Normal completion belongs to the engine; crash recovery belongs to the EXEC
order. N controls context recycling; K controls concurrent seats. Recycling is
amortized over N accepted submissions, with additional claim and lifecycle bead
writes. The measured fresh-context cost motivates the N recommendation below.

\section{Problem directory and configuration}
A problem may live anywhere on disk. Except for the bundled example it lives in
the rig that uses it, never in the pack. The mutator receives a task-local
presentation rather than direct access to this directory.
\begin{lstlisting}
<problem>/
  problem.toml    # config (below)
  problem.md      # the maths in prose: goal, what is known, hints. This is what the mutator reads.
  candidate.h     # exact C prototypes the candidate must export, with comments
  seed.c          # the starting candidate, usually trivial
  evaluator/      # evaluator source + build script (or a prebuilt .so)
  runs/           # created by the engine, gitignored: one subdirectory per run
\end{lstlisting}
The v1 \code{problem.toml} schema below preserves the epic's generic example
and defaults; the bundled cap-set evaluator instead uses
\code{evaluator/libcapset.so} and \code{memory\_mb = 4096} for embedded Julia.
The instance is opaque to the engine: exactly one is used per run, passed
unchanged to \code{fs\_init} and \code{fs\_score}. Override it with
\code{--instance}; repeat \code{--set key=val} for typed dotted-key overrides.
The config loader accepts all known schema keys (also \code{instance=S} as an
alias for \code{problem.instance}). The formula launcher accepts only
\code{search.*} and \code{stop.*} overrides; instance uses its separate
formula variable and mutator model comes from \code{problem.toml};
shell-command keys (\code{candidate.compile*}, \code{evaluator.build})
come only from \code{problem.toml}.
\begin{lstlisting}
[problem]
name = "cap-set"
instance = "n=6"                 # default instance, overridable per run

[candidate]
language = "c"
compile = "cc -O2 -shared -fPIC -o {out} {src}"          # {src}, {out} substituted
compile_try = "cc -O1 -g -fsanitize=address,undefined -shared -fPIC -o {out} {src}"  # for `try`
exports = ["priority"]           # symbols that must be present in the .so (checked with nm / dlsym)

[evaluator]
build = "make -C evaluator"      # run once at run start in the problem dir; may be empty
library = "evaluator/libevaluator.so"
timeout_s = 30                   # per fs_score call
memory_mb = 2048                 # RLIMIT_AS for the worker

[search]
islands = 4
mutators = 3                     # K = number of slot beads
tasks_per_session = 1            # N: tasks a mutator session handles before recycling
trial_budget = 3                 # max `try` calls per task
parents_per_task = 2
workers = 2                      # worker processes PER POOL (submit + try)
reset_period_s = 1800            # weakest-half island reset period

[stop]
duration_s = 3600
max_children = 100
plateau_children = 0             # 0 = disabled; else stop after this many children with no improvement

[mutator]
model = "claude-haiku-4-5-20251001"
\end{lstlisting}
The normal compiler is used for authoritative submission; \code{compile\_try}
adds sanitizers for trial evaluation. Required exports are checked with
\code{nm -D --defined-only}, or isolated \code{ctypes.CDLL} inspection when
\code{nm} is unavailable. Each compilation uses a private immutable source
copy and the saved \code{candidate.h}, a 60-second compiler timeout, and a
4 KiB diagnostic limit. Evaluator builds run in the problem directory with
a 15-minute timeout; an empty build command supports a prebuilt library.

The problem-setup skill and templates live in
\path{skills/funsearch-problem-setup/}. A copied template should set its build
command to \code{make -C evaluator FS\_PACK=/absolute/path/to/pack}, since a
formula agent need not inherit the experimenter's exported \code{FS\_PACK}.
Use \code{check} before launching a search.

\section{Evaluator C contract and author rules}
The following is the verbatim design-section-5 contract for the pack's
\code{include/funsearch.h}. An evaluator can use any implementation language
behind this ABI, including a C wrapper embedding Julia.
\begin{lstlisting}[language=C]
typedef enum { FS_OK = 0, FS_INVALID = 1, FS_ERROR = 2 } fs_status;
typedef struct {
  fs_status status;
  double    score;      /* higher is better; meaningful only if FS_OK */
  /* Optional signature: up to 8 finite values (e.g. per-size scores) that
   * group programs into clusters (rounded to 8 decimals). It never ranks.
   * An FS_OK submission with exactly the same score and sig as an active OK
   * program is rejected as a duplicate, so with nsig = 0 every submission
   * that ties an existing score is a duplicate whatever its code. */
  int32_t   nsig;       /* 0..8 */
  double    sig[8];
  char      msg[256];   /* shown to the mutator during `try`; NUL-terminated */
} fs_result;

/* resolve(sym) returns the address of symbol `sym` in the candidate, or NULL. */
typedef void *(*fs_resolve_fn)(const char *sym);

/* REQUIRED */
fs_result fs_score(fs_resolve_fn resolve, const char *instance);
/* OPTIONAL: called once per worker process before any fs_score / at shutdown. */
int  fs_init(const char *instance);   /* nonzero = fatal: the run fails at startup */
void fs_fini(void);
\end{lstlisting}
\begin{itemize}
\item Never return \code{FS\_OK} without independently checking the object the
candidate produced. That check must not call the candidate.
\item Use exact or interval arithmetic where floating-point errors could be exploited.
\item Explicitly reject degenerate outputs with \code{FS\_INVALID} and a clear
\code{msg}. The verifier-loophole lesson motivates this responsibility
\cite{exploration}.
\item Internal structure---multiple sizes, a cheap-first cascade, or early exit---is
the evaluator's business. Return one score; per-size values may appear in \code{sig}.
\end{itemize}
Scores are higher-is-better doubles and meaningful only for \code{FS\_OK}.
Signatures contain at most eight doubles. The status distinguishes invalid
objects from evaluation errors, while the NUL-terminated message explains feedback
to the mutator during trials.

\section{Worker protocol}
\code{funsearch-worker <evaluator.so> <instance>} loads the evaluator once.
If present, \code{fs\_init} runs before any score call; a nonzero result prints
an error line and exits 3, failing run startup.

There is one request per stdin line and one JSON result per stdout line:
\begin{lstlisting}
SCORE [#<hex token> ]<absolute path to candidate .so>
{["nonce":"<token>",]"status":"OK|INVALID|ERROR","score":<num>|null,"sig":[...],"msg":"..."}
SYNC #<hex token>
{"sync":"<token>"}
QUIT
\end{lstlisting}
For each SCORE request, the worker opens the candidate using
\code{dlopen} with flags \code{RTLD\_NOW|RTLD\_LOCAL}, binds a resolve function to
\code{dlsym} on that handle, calls \code{fs\_score}, then \code{dlclose}s it.
The worker evaluates one candidate at a time. JSON has no NaN, so an
\code{OK} result with a non-finite score or signature value becomes
\code{ERROR} (``non-finite score''/``non-finite signature''). An
\code{INVALID} or \code{ERROR} result keeps its own status and message: a
non-finite score is sent as \code{null} and a non-finite signature is dropped
(empty \code{sig}). When the request carries a token, the reply echoes it; the
engine always sends one and discards replies without it. The worker reads
requests with \code{read(2)} and wipes them before candidate code runs. After
each reply the engine sends a \code{SYNC} barrier and requires its echo as the
next line, so a forged reply carrying the token is exposed by the worker's own
reply that follows it; output after the barrier replaces the worker before the
next request. Candidate code shares the worker process, so this raises the bar
against forged results without being an isolation boundary. On \code{QUIT}, it calls
\code{fs\_fini} if present and exits 0; EOF also runs finalization. The worker
reserves a protocol stream and redirects evaluator/candidate stdout to stderr
so native output does not corrupt JSON replies. It restores blocking stdin
after evaluator initialization, including when embedded Julia changes its flags.

The engine owns timeouts and crash handling: it kills the worker on timeout,
records \code{ERROR} with ``timeout'' or ``worker crashed: signal N'', and
starts a replacement worker. If \code{FS\_MEMORY\_MB} is set, the worker uses its value to apply the
\code{RLIMIT\_AS} memory limit through \code{setrlimit}. It must not install SIGSEGV handlers:
embedded Julia uses its own. The daemon creates separate final and sanitizer
pools, each with \code{search.workers} processes started eagerly and kept for
the whole run, so a run holds twice that many resident evaluators and an idle
pool cannot lend capacity to the other. Sanitizer workers preload
libasan and remove \code{FS\_MEMORY\_MB}: ASan's virtual shadow mapping otherwise
fails under \code{RLIMIT\_AS}. Final workers keep the configured address-space
limit. Trials keep scoring timeouts and bound memory in ASan's terms instead:
\code{hard\_rss\_limit\_mb} and \code{max\_allocation\_size\_mb} equal
\code{evaluator.memory\_mb}. The engine
waits for worker initialization using a blank-request protocol probe; fatal
initialization fails the run, while other startup failures have bounded retries.
A warm evaluator process is therefore reused across
candidates, while each candidate library has a per-request lifetime.
Both pools recycle after 100 completed scoring replies, before the next
request and its timeout. The fixed budget avoids allocator/GC memory-noise
restarts and bounds retained candidate state; it cannot prevent an individual
candidate or burst of leaks from exhausting memory earlier. Native stderr is
continuously drained into a bounded 1 MiB tail, with the last 2 KiB included
in startup, crash, protocol and timeout failures.
The cap-set C wrapper disables libblastrampoline deep binding only when a
preloaded ASan runtime is detected, allowing embedded Julia sanitizer trials;
normal final evaluation keeps its usual loading behavior.

\section{Engine: CLI, database, and evolution}
The engine uses Python 3.11 or later, its standard library and SQLite, without
third-party Python dependencies. Its entry point is \code{bin/funsearch}.
A C compiler, \code{make}, \code{flock}, and POSIX process facilities are also required.
\subsection{Command-line contract}
\begin{lstlisting}
funsearch check <problem> [--instance S]
funsearch run start <problem> [--instance S] [--run-id ID]
    [--set key=val]... [--on-start CMD] [--on-finish CMD]
funsearch run status <run-dir>
funsearch run recover <run-dir>
funsearch best <run-dir> [-k N]
funsearch stop <run-dir>
funsearch next-task <run-dir> [--slot ID]
funsearch try <run-dir> <task-id> <candidate.c>
funsearch submit <run-dir> <task-id> <candidate.c>
funsearch rescore <run-dir> <program-id|best> --instance S
funsearch slot show <bead-id>
funsearch slot release <bead-id>
funsearch slot close <bead-id>
\end{lstlisting}
\begin{description}
\item[check] Validates the directory and TOML, builds the evaluator, compiles the
seed, scores it with a fresh worker, and prints JSON. It performs no search.
\item[run start] Snapshots the evaluator library's directory, performs pre-flight
with that snapshot (seed must score \code{FS\_OK}), then saves inputs,
configuration and the same snapshot as \path{<run>/evaluator/}. Workers and
rescore load that copy, so the seed and the run are scored by identical files;
\code{run.json}'s \code{evaluator\_sha256} is \code{evaluator\_digest} of it: the
SHA-256 of the sorted JSON list of \code{["file", path, sha256]} and
\code{["link", path, target]} entries, not a \code{sha256sum} of the library. The
library must therefore sit in its own subdirectory, never in a directory containing
the problem's \path{runs/}. Symlinks are copied as links, so each must be
relative and resolve inside that directory; any other link is refused. The command then starts the detached daemon. The daemon owns both hooks:
it runs the start hook after worker-pool readiness and before dispatching any
evaluation, so the run never depends on the launcher surviving. \code{run start}
returns after that readiness, printing \code{<run-id> <absolute-run-dir>}.
Optional hook commands receive the run directory as an argument, with
\code{FS\_RUN\_DIR} also set. Each hook must exit within 120 seconds; on
timeout its whole process group is killed and the hook counts as failed, so a
slow start hook fails the run. The engine never calls \code{gc};
\code{bin/funsearch} hands \code{slot} to the Gas City layer in
\path{scripts/gc_lifecycle.py}.
\item[run status / best / stop] Inspect JSON run state, list top programs
(default ten), or request graceful termination through SQLite.
\item[run recover] For a run whose engine died, writes failed outputs from the
live database or the newest readable snapshot. It refuses while the engine
PID is alive, and for a run whose summary already records a terminal status.
\item[next-task] Prints \code{TASK <task-id> <absolute-task-dir>} containing
\code{TASK.md}: problem prose, candidate header, scored parents and messages,
a recent-history summary, trial budget, and instructions. If stopped it prints
\code{RUN\_OVER} and exits 3.
\item[try] Compiles with \code{compile\_try}, scores through the sanitizer pool,
and prints \code{RESULT <status> <score> <message>}. The score is meaningful
only for \code{OK}; a non-OK result without one prints 0. Trial reservation is atomic;
a compile failure consumes a trial and records ERROR. Exhausted budgets refuse
further trials.
\item[submit] Normalizes and hashes code and rejects active normalized duplicates
before scoring, or active OK behavior duplicates afterward. Rejection leaves
the task open. Otherwise it compiles with \code{compile}, scores authoritatively,
stores the child, and closes the task. Output is
\code{ACCEPTED <program-id> <status> <score>}, with the same score rule as
\code{try}. INVALID/ERROR children are stored
as history but never sampled as parents. Mutator-reported scores are ignored.
\item[rescore] Prints JSON from a temporary final worker scoring a stored program
on another instance; the original run retains its single instance.
\item[slot show / release / close] Inspect a claimed slot and unfinished task,
return it to the pool, or close it on RUN\_OVER. These Gas City adapters check
session ownership and are described below.
\end{description}
Exit codes are 0 (success), 1 (runtime/seed failure), 2 (usage/configuration
error), 3 (RUN\_OVER for task commands), and 4 (rejection or exhausted budget).
Status, best, and rescore remain usable after completion. Each try/submission
compiles a private source copy with the saved \code{candidate.h}; the immutable
request sources remain available for independent verification.

\subsection{Storage and evolutionary policy}
\code{<run-dir>/db.sqlite} uses DELETE rollback journaling, foreign keys, and a
5000 ms busy timeout. Writable opens migrate existing WAL databases; stop legacy
engines/clients before migration. Status, best, rescore, and mutator inspection
open read-only \code{mode=ro} connections without schema writes. The layout is
versioned by \code{PRAGMA user\_version}; only the engine (daemon start, and
recovery after it exits) migrates an older run, and clients refuse a run whose
version differs. WAL was replaced
after a two-process probe reproduced SIGBUS on the host-mounted pack directory
but not on the overlay filesystem. Snapshots also use DELETE.
Under rollback journaling readers and the writer exclude each other. The
engine retries a tick whose database access stays locked past the busy timeout
and fails the run only after 60 seconds without a successful tick, and
snapshots normally copy the database in 1024-page steps so client writers wait
for one step. After three restarts caused by client writes, the backup finishes
in one pass that blocks writers for the whole copy. This is sized for one host
and a handful of mutators per run; much larger mutator counts or source histories
would need measuring first.

The database stores programs (ID, parent IDs, island, source, normalized hash,
status, score, signature, message, timestamps), tasks, trials, an evaluation
queue, and run state. The daemon owns the worker pools and queued evaluations;
CLI processes and the daemon communicate only through SQLite.

Evolution maintains islands with clusters keyed by (score, signature rounded
to eight decimal places). Tasks rotate through islands. Parents are sampled
without replacement using Boltzmann weights over range-normalized cluster scores,
with a cyclic temperature schedule decreasing within each 30,000-program period;
shorter programs are preferred within a cluster. Periodic resets archive the
weakest floor(number of islands / 2) islands and reseed from randomly selected
survivors' best programs. Old programs remain readable by existing tasks.
Signatures never rank programs; score alone determines quality.

Duplicate checks cover active programs: normalization hashes C tokens while
preserving literals and preprocessor distinctions; behavior duplicates require
an exactly equal OK score and signature, unlike rounded clustering. Recent
history includes archived children and the first real \code{// IDEA:} comment.

\subsection{Stop and durable output}
The engine owns duration, \code{max\_children}, plateau, and explicit-stop
conditions. \code{plateau\_children = 0} disables plateau stopping; otherwise
stop after that many submitted evaluations without improvement.
\code{children\_scored} counts authoritative submitted evaluations, including
post-score duplicate rejections; trials and compile failures do not count.
In-flight reservations prevent max-child overshoot. Queued requests receive
RUN\_OVER at stop, and active work gets a bounded 120-second completion window.
Open tasks older than twice (trial budget times scoring timeout plus 600 seconds)
are abandoned when they have no queued or running evaluation.

On stopping, the engine writes \code{summary.json}, exports \code{best.c} and
up to ten distinct OK programs as \code{top/<rank>-<score>.c}, shuts down workers,
runs the finish hook, and exits. Snapshots every 600 seconds and at completion
use SQLite's backup API; the latest five live in \code{snapshots/}.

\code{engine.log} contains flushed UTC startup, shutdown and signal events,
worker errors, and fatal-signal tracebacks. SIGTERM, SIGHUP and SIGINT request
graceful shutdown. A detached parent waits for the daemon and records its exit
code and signal in \code{engine-exit.json}. Before forking the engine, that
observer execs with the launching agent's identity removed, including
\code{GC\_SESSION\_ID}, \code{GC\_SESSION\_NAME}, and \code{GC\_AGENT}, so Gas
City's process-table orphan reaper cannot retire it with the launcher.
City, rig and notification context remain available to hooks. The exit record
requires the observer to survive; SIGKILL alone does not establish an OOM cause.
Liveness instead rests on an exclusive \code{flock} the engine holds on
\code{engine.lock} in the run directory for its whole life. The kernel drops it
however the process tree is lost, so clients, \code{run status}, \code{run
recover} and the Gas City sweep never mistake a process reusing the engine's PID
for the engine. A run directory without the lock has no live engine.

\section{Mutator role}
\path{agents/mutator/agent.toml} defines the rig-scoped
\code{funsearch.mutator} Claude pool with default model
\code{claude-haiku-4-5-20251001}, zero minimum sessions, cap three, and
\code{wake\_mode = fresh}. Increase the importing rig's cap for larger K or
concurrent runs, allowing for rig/workspace limits. The problem's
\code{[mutator] model} is copied to slot \code{opt\_model} metadata.
Each concrete session has a private working directory under
\path{<city>/.gc/funsearch/mutators/}.

\subsection{Actual tool restriction and trust boundary}
The \code{pre\_start} command runs \path{scripts/mutator_setup.py} to install
project Claude settings and a mandatory \code{PreToolUse} guard.
Claude runs in \code{dontAsk} mode (the provider's \code{full-auto} option),
with Bash/Read/Write/Edit only, project settings only, an empty strict MCP
configuration, and slash commands disabled. \path{scripts/mutator_guard.py}
grants only literal calls to this pack's next-task/try/submit and slot helpers,
\code{gc hook --claim --json} (optionally \code{--drain-ack}), and
\code{gc runtime drain-ack}. Shell composition/substitution, other commands,
and wrong runs/slots/tasks are denied. File tools can read only the current
\code{TASK.md} and \code{child.c}; only \code{child.c} is writable.
Paths with shell metacharacters are unsupported; quoted spaces are allowed.

\subsection{Trust model (v1)}
Candidate C programs written by LLM mutators are compiled and run natively as
the invoking user, with that user's filesystem and network access. The mutator
tool guard and compile source policy keep honest mutators on task and catch
accidents. They are \textbf{not a security boundary} and do not contain
adversarial code. Use v1 only for trusted local experiments. OS-level isolation
is future work, tracked in backlog bead \code{mc-v8f3.5}.

This enforces a Claude tool policy, and it is not a boundary against the
mutator itself. Gas City's agent schema supplies no OS filesystem/network
sandbox. The guard must allow \code{try} and \code{submit}, which compile and run
the mutator's C with the host user's access; that code can rewrite the
session's generated settings, slot context and run state, and use the city.
\code{TASK.md} embeds other candidates' source, a prompt-injection channel.
The compile source policy is a best-effort lint for common mutator accidents:
it rejects suspicious includes, \code{\#embed}, inline assembly and token
pasting. It may reject inert text or miss compiler-specific forms. It does not
isolate compilation or prevent arbitrary filesystem reads or diagnostic
disclosure. Candidate code gets an allowlisted environment (locale,
\code{PATH}, \code{HOME}, \code{TMPDIR} and the problem's \code{evaluator.env}
patterns); replies must echo a per-request token. These hygiene measures do
not contain native code. V1 supports trusted local experiments only; OS-level
isolation remains backlog work (\code{mc-v8f3.5}). Symlink swaps by other
processes remain a race. Pack code/settings must be trusted, and launch overrides
must preserve hooks, project settings, permission mode, tool and MCP restrictions.
City-managed trusted lifecycle hooks operate outside the model's tool allowlist.

\subsection{Slot ownership, release and fresh retirement}
A session claims with \code{gc hook --claim --drain-ack --json}.
It uses \code{funsearch slot show <bead>} to load \code{fs.run\_dir}, \code{fs.slot},
and \code{fs.tasks\_per\_session}. Show also reports an unfinished task and
used trials so a replacement resumes it without allocating a second task.
After N accepted submissions, release performs a guarded \code{gc bd update}
with \code{--if-assignee} and \code{--if-status=in\_progress},
\code{--status=open}, and an empty assignee. It clears session/claim/worktree
metadata while preserving \code{gc.routed\_to}.

On RUN\_OVER, close uses the same guards with \code{--status=closed}; an
already closed slot is a read-only success. Neither helper drains. A successful
release/close writes \code{.funsearch-retired.json}, making the tool guard
permit only \code{gc runtime drain-ack} for that retiring session. This prevents
a late nudge from reclaiming the slot in the same provider context before the
controller finishes drain. A different session ignores the old receipt.

\section{Gas City integration}
\subsection{Formula and beads}
\path{formulas/funsearch-run.toml} is a single plain start step requiring
formula compiler v2. \code{pack}, \code{problem} and \code{notify} are required;
\code{instance} and \code{overrides} default to empty. Notify has no inferred
slinger default: Gas City exports no reliable slinger recipient. After importing
the pack into any rig, launch on that rig's general coding-agent pool:
\begin{lstlisting}
gc sling <rig>/<pool> funsearch-run --formula \
  --var pack=/absolute/path/to/funsearch-pack \
  --var problem=/absolute/path/to/problem \
  --var instance=n=6 --var notify=<recipient> \
  --var 'overrides=search.mutators=3 stop.duration_s=3600 stop.max_children=100'
\end{lstlisting}
The start agent takes the pack root from the required \code{pack} variable,
and stops for the operator if that path does not contain the pack CLI. It then
calls \path{scripts/gc_lifecycle.py} launch with literal quoted values.
That helper parses overrides as data, invokes run start with on-start/on-finish
hooks, and supplies \code{FS\_NOTIFY}. The start step records run ID/directory
and closes while the search continues. There is no generic formula-agent
\code{PACK\_DIR} assumption, so the operator supplies \code{pack}. Resume uses the recorded run rather than relaunching.

The start hook creates a \code{funsearch-run} bead in the starting rig and K
child \code{funsearch-slot} beads, routed raw with \code{--no-formula} to
\code{<rig>/funsearch.mutator}. Run metadata uses \code{fs.*} keys for problem,
run directory, instance, PID, status, counters and notify. Slots carry run/slot,
N and model metadata. \path{gc-lifecycle.json} beside the engine's write-once
\code{run.json} saves bead IDs, city/rig/notify context, and lifecycle
checkpoints. The registry at
\path{<city>/.gc/funsearch/active/<run-id>.json} stores run ID, run directory, run
bead, rig and notify; run IDs must be unique across the city.

\subsection{Completion and crash sweep}
The start and finish shell hooks delegate to \path{scripts/gc_lifecycle.py}.
Finish records best versus seed, scored children,
throughput, OK rate, reason and \code{best.c}. It lists all slot children,
including claimed/blocked/deferred slots, force-closes them before their parent,
sends completion mail (not a nudge) to notify, and removes the registry entry.
The engine/sweep owns terminal cleanup even when a live mutator owns a slot.

\path{orders/funsearch-sweep.toml} is a condition-triggered EXEC order, without
an agent, with a ten-second check timeout and five-minute execution timeout.
The shell wrappers invoke the Python sweep. Its check returns 0 only with active
JSON entries and a missing or more-than-30-minute-old last-sweep timestamp.
False checks create no tracking beads. A city-wide lock prevents overlapping
sweeps from importing rigs. Live engines (held \code{engine.lock}) are untouched; dead engines without a
terminal summary run \code{funsearch run recover}, which writes failed/engine
died outputs from the live database or the newest readable snapshot. Dead engines with a terminal summary retry delivery with
the actual outcome preserved. The sweep updates its timestamp even on errors,
which retain registry entries for another retry.

Hooks serialize per run and checkpoint completed actions. Sequential retries do
not resend completion mail, but a crash between an external successful action
and its JSON checkpoint can repeat a note, bead creation or mail: the stores do
not share a transaction. A manual retry is
\code{<pack>/scripts/on-finish.sh <run-dir>}; saved context restores rig/recipient
from any cwd. Direct hooks require city, rig and notify environment. Runs are
gitignored and no source or result is automatically committed.

\section{Cap-set example and acceptance}
The bundled problem lives at \code{examples/cap-set/}. Its candidate ABI is
\begin{lstlisting}[language=C]
double priority(const int8_t *v, int32_t n);
\end{lstlisting}
Here \code{v} has length n, with entries in $\{0,1,2\}$. The evaluator is a C
wrapper embedding Julia (libjulia). Its \code{fs\_init} starts Julia once and
loads \code{capset.jl}. Its \code{fs\_score} calls a Julia greedy construction
that \code{ccall}s the resolved priority pointer, then independently checks that
the produced set is a cap set. For distinct $x,y,z\in\mathbb{F}_3^n$, the
forbidden condition is
\[
 x+y+z\equiv 0\pmod 3.
\]
The verifier does not call the candidate. Score is the cap size $|C|$ at n
from the instance (default \code{n=6}), and the signature contains cap sizes
at $n=4,5,6$ for the default instance. For $n<4$ it evaluates sizes $1,\ldots,n$;
for $n=4,5$ it evaluates $4,\ldots,n$; for $n>6$ it also appends the target n.
The evaluator rejects non-finite priorities and input mutation and uses
lexicographic tie breaking. The seed returns constant priority. The original
design records known optimum sizes $2,4,9,20,45,112$ for $n=1,\ldots,6$.
The independent checker is \path{tools/check_cap.py}; \code{FS\_CAPSET\_DUMP}
optionally records generated caps. The formula provides no documented
environment passthrough, so acceptance enabled dumps during independent replay.

The acceptance bead runs in rig \code{math-experiments}, with 3 mutators,
for about one hour or 100 children. It passes when the run completes unattended,
the best score strictly exceeds the seed score, and every recorded cap passes
an independent re-check. It reports throughput, share of children scoring OK,
session startup cost, and a recommended N (tasks per session). The final
acceptance result follows; earlier failures remain in the acceptance report.

\section{As built: changelog versus original design}
\begin{itemize}
\item \textbf{Storage:} WAL became DELETE rollback journaling, with read-only
inspection clients and backups, after mount-specific SIGBUS reproduction.
\item \textbf{Native execution:} final and sanitizer pools are separate;
ASan trials replace the address-space limit with ASan RSS and allocation
limits of the same size. Compilation uses immutable
copies, bounded subprocesses and export inspection. The worker restores blocking
stdin after Julia initialization and keeps native stdout off the JSON protocol.
\item \textbf{Daemon lifecycle:} flushed signal/death diagnostics and an exit
observer were added. Observer re-exec strips launcher identity to survive Gas
City's orphan reaper; setsid alone was insufficient.
\item \textbf{CLI and configuration:} repeated \code{--set}, slot
show/release/close adapters, actual output/exit conventions, typed engine
overrides and search/stop-only formula overrides, top-file naming, snapshot retention, and child-count semantics are
specified here. Cap-set uses \code{libcapset.so} and 4096 MiB instead of the
generic schema example's library and 2048 MiB.
\item \textbf{Gas City mechanics:} a plain one-step v2 formula requires explicit
notify, resolves the imported pack through CLI introspection, and raw-routes
slot children. Finish force-closes claimed slots before the parent; locked,
checkpointed retries and the city-wide sweep preserve terminal outcomes.
\item \textbf{Mutator restriction and recycling:} Claude project settings and
PreToolUse implement a tool policy, not OS isolation. Ownership/status-guarded
slot updates preserve routing. A retirement receipt enforces drain-only behavior
and prevents same-context reclaim during delayed controller retirement.
\item \textbf{Evidence:} live cap-set acceptance passed with score 82 versus 64,
independent replay and exact checks. Measured startup recommends testing N=5;
wall-time, host resource, compiler-mode and seat-utilization limits remain explicit.
\end{itemize}

\section{Decision log: Q1--Q24}
The epic records the resolved design, not the original interview transcript.
Except for the supplied Q16 example, the Q labels below are a reconstruction
for this record, derived from the design; they do not claim original question wording.
They preserve the original decisions; the changelog above records as-built changes.
\begin{enumerate}
\renewcommand{\labelenumi}{Q\arabic{enumi}:}
\item Package the search as a project-agnostic Gas City pack named \code{funsearch}.
\item Use an agentic mutator that writes, compiles, and tests whole candidates.
\item Trade sample volume for per-child quality; plan for hundreds of children.
\item Publish an Apache-2.0 pack submodule and credit any kitft-derived code in NOTICE.
\item Keep each problem self-contained in a directory owned by its using rig.
\item Use exactly one opaque instance string per run, passed unchanged through the ABI.
\item Start with C candidates exporting the problem's \code{candidate.h} symbols.
\item Put all problem knowledge in a user-supplied shared evaluator with a C ABI.
\item Return status, one higher-is-better double score, optional signature, and message.
\item Use at most eight signature doubles for clustering and duplicates, never ranking.
\item Require independent validation, exact/interval checks, and explicit invalid-output rejection.
\item Reuse a C worker's evaluator, resolving and unloading each candidate per request.
\item Let the engine replace timed-out/crashed workers; apply RLIMIT\_AS and no SIGSEGV handler.
\item Use a dependency-free Python/SQLite WAL engine, with queue-only CLI/daemon communication.
\item Own normal stopping in the engine and export summaries, best code, and backup-API snapshots.
\item The engine finishes its own runs; a dormant condition-triggered EXEC order sweeps crashes every $\geq$30 minutes (the check requires more than 30 minutes since the last sweep).
\item Evolve islands using (score, signature) clusters, Boltzmann parent sampling, shorter-code preference, and weakest-half resets.
\item Offer pre-flight, start/status/best/stop, next-task/try/submit, and alternate-instance rescore commands.
\item Bound trials per task, rescore submissions authoritatively, and reject duplicates without consuming tasks.
\item Restrict mutators to task-local files and search commands, defaulting to Claude Haiku with a problem override.
\item Represent K concurrent seats by raw-routed slot beads and recycle fresh sessions after N tasks.
\item Keep Gas City outside engine core: thin run formula, lifecycle hooks, registry, run bead, and completion mail.
\item Bundle the Julia-backed cap-set problem; require unattended improvement, independent rechecks, and throughput/startup measurements.
\item Land locally through per-bead worktrees, run one whole-epic review, then push and refresh documentation at close-out.
\end{enumerate}
